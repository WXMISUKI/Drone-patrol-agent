03主链与分支

建议按以下路径演示，能覆盖“自动流转 + 人工闸门 + 退回”三种关键行为：

01编排下发

自然语言 → 航线 → 合规检查 → 下发

02飞行回传

航迹、遥测、影像、AI 命中

03人工复核

证据 + 依据 → 确认 / 误报 / 存疑

04整改复核

派单 → 上报 → 对比 → 销号或退回

05报告归档

数据现算 → 版本 → 审核签发

分支演示

  • 一般隐患自动流转：在复核台选择低风险样本，或在流程运行台查看 conf ≥ 0.85 且 level=general 的实例，状态直接进入 PENDING_RECTIFY。
  • 重大隐患强制人工：复核台的 018 号隐患，确认前必须填写复核意见与现场核实方式；状态机守卫不允许跳过。
  • 复核退回：在整改闭环页点击“退回整改”，流程回到 PENDING_RECTIFY，整改时限重算，连续两次退回升级建设单位。
  • 误报回流：复核台“标记误报”需选择原因，样本进入坏例库，参与下一轮提示词与模型评估。

04状态机与守卫

与开发方案 3.2.2 保持一致。原型中的状态机是同一份定义的视觉表达，研发实现时以代码为准。

转换触发条件守卫 / 约束
INIT → AI_ANALYZING输入数据完整必填字段校验、影像存在
AI_ANALYZING → PENDING_RECTIFY一般隐患且置信度 ≥ 0.85Worker 输出合法、自动入库权限
AI_ANALYZING → PENDING_HUMAN_REVIEW重大隐患或 0.60 ≤ 置信度 < 0.85强制人工，不可自动跳过
AI_ANALYZING → REJECTED人工确认误报监理角色、误报原因必填
PENDING_HUMAN_REVIEW → PENDING_RECTIFY人工确认隐患监理 / 建设单位权限
PENDING_HUMAN_REVIEW → REJECTED人工驳回驳回原因必填
PENDING_RECTIFY → PENDING_RECHECK施工方提交整改所属标段责任人校验
PENDING_RECHECK → CLOSED复核通过监理确认、证据齐全
PENDING_RECHECK → PENDING_RECTIFY复核不通过退回原因必填
任意 → FAILED系统异常自动告警、支持断点恢复

实现约束

  • 状态转换只允许通过 Supervisor 接口发生，Worker 不得直接写业务状态。
  • 权限在 API 依赖注入与状态机守卫中双重校验，数据查询自动附加标段过滤。
  • 所有转换写入审计日志，包含操作人、时间、前后状态、原因与 trace id。
  • 提示词、状态机定义、报告模板均纳入 Git 与版本号管理。

06接口建议

仅列原型涉及的关键接口，完整 OpenAPI 由 FastAPI 自动生成。

方法路径用途权限
POST/api/v1/missions创建/下发巡视任务，返回任务号与流程实例监理 / 建设
POST/api/v1/webhooks/vision接收视觉识别结果，触发隐患研判流程服务间鉴权
GET/api/v1/hazards/{id}隐患详情：检测框、研判、引用、复核记录按标段

POST/api/v1/workorders/{id}/recheck复核通过销号或退回整改监理
POST/api/v1/reports生成报告草稿，返回版本号监理以上
POST/api/v1/knowledge/query知识问答，返回答案、引用与拒答标记按角色

Webhook 事件

vision.detected

视觉服务完成一批影像检测，携带 detections 与影像 ID。

mission.landed

架次降落，触发影像归档、质量检查与补飞判断。

rectify.submitted

施工方提交整改，Supervisor 恢复流程至待复核。

report.issued

报告签发，触发归档与通知订阅方。

07设计系统

视觉语言取自“工程控制台 + 航测图纸 + 纸面台账”：暖纸底、深海军蓝导航、砖橙强调色，数据用窄体数字，状态用语义色而非装饰色。

主色

#C2502C 操作与品牌

确认

#146B5D 通过 / 已闭环

重大

#B02A21 重大隐患 / 阻断

字体

UI 使用系统中文黑体；数字用 Bahnschrift；编号与代码用等宽字体，保证台账对齐。

密度

基础字号 13px，表格行高 36—40px；面板 1px 描边、4—6px 圆角，不用大圆角与重阴影。

影像

航拍图统一降饱和、压暗边缘；检测框使用橙色 1.5px，标签贴在框左上角，避免遮挡证据。

可复用组件

状态机轨道 .rail、调用链 .trace、证据框 .bbox、法规引用 .cite、前后对比 .compare、指标卡 .metric、报告纸面 .paper。全部为原生 CSS，无外部依赖。

08验收清单

原型评审通过后，研发按以下条目逐项确认；标“必须”的项不通过则不能进入开发联调。

✓
主链完整：编排 → 飞行 → 复核 → 整改 → 报告，五段可连续走通。
✓
人工闸门：重大隐患无法绕过复核直接派单。
✓
权限可见：切换监理/建设/施工，操作按钮与数据范围同步变化。
✓
证据可追溯：每个隐患可回到原图、任务、桩号与规范条款。
✓
状态一致：页面状态与流程实例状态同名，不出现两套说法。
✓
版本受控：报告每次修改生成新版本，签发后锁定。
✓
无依据拒答：问答在检索分数不足时明确拒答，不编造条款。
✓
弱网可用：现场端展示离线缓存与待同步，不阻塞整改。
✓
审计留痕：复核、退回、销号、导出均有操作记录。
✓
可离线演示：不依赖 CDN、字体服务或后端接口。
