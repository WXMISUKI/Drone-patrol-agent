# 项目启动草案（待讨论）

状态：探索中；本文件不是已批准的 PRD、MVP 规格或技术设计。日期：2026-11-11。

## 已提供的方向

面向施工总包、建设单位和监理，以 Web 管理后台为入口，围绕大范围、地形复杂工地，探索无人机影像采集、AI 辅助识别、人工研判、整改复核和报告。领导描述包含航线与设备、影像管理、识别研判、闭环报告、平台集成五个能力域，产品定位为按项目适配的半标品。

参考功能清单还涵盖工程量、三维建模、多载荷与多行业专项；是否纳入产品及其优先级均待确认。参考原型含后台与移动端，交接页列出状态、契约、接口和假设；这些均是讨论素材，不是已认可的架构或实现约束。

## 假设与验证边界

- 候选主链：影像进入系统 → 识别产生候选问题 → 人工确认 → 整改与复核 → 报告；具体责任人、状态和集成边界待核实。
- 优先用真实项目与样本验证影像可用性、隐患可见性、定位精度和业务价值。AI 输出是辅助线索，不能替代专业人员的安全结论。
- “分钟级”“30 倍”“85%”等表述及不同参考材料中的效率、覆盖范围指标，均为待验证目标或宣传设想；需明确对象、基线、方法和条件，不能作为现有能力或验收承诺。
- 自动飞行、空域和设备安全能力依赖设备、服务商、现场流程与适用要求；具体责任边界和规则须由相关方确认。

## 建议的阶段及交付物

1. 资产盘点与场景访谈：明确项目、角色、现有系统和数据；形成资产清单与问题记录。
2. 多角色研讨：产品、业务安全、无人机作业、AI/数据、架构、交付及测试分别提出目标、限制和冲突，记录来源与待决事项，由业务负责人决策。
3. 需求与范围：整理功能清单、业务流程、非功能要求、验收指标及 MVP 候选，明确范围外事项，形成待评审 PRD。
4. 原型和技术可行性：针对选定主链制作原型并评审；并行验证设备接口、影像、识别效果与部署边界，再细化技术设计。
5. MVP：将确认范围写入 OpenSpec，分解任务，按可验证的业务切片实现，进行样本、现场及业务验收；再决定扩展方向。

各阶段允许回退迭代；文档与原型应服务决策，不以产出数量为目标。

## 多角色研讨提纲

| 视角 | 重点问题 | 期望输出 |
| --- | --- | --- |
| 产品 / 项目 | 首个客户、痛点、成功指标、投入和范围 | 场景与优先级 |
| 施工安全 / 监理 | 哪些隐患从空中可见，如何确认、整改与销号 | 业务规则与样例 |
| 飞行作业 / 设备 | 机型机巢、航线、采集质量、控制权限和责任 | 设备接入及作业约束 |
| AI / 数据 | 样本可用性、误报漏报、定位、评价方法 | 验证方案与边界 |
| 架构 / 交付 | 对接系统、网络、离线范围、权限与部署 | 集成约束和候选方案 |
| 测试 / 验收 | 基线、场景覆盖、可测指标和现场验收 | 验收草案 |

## 首批待确认事项

1. 首个试点工程类型、具体使用方与最终业务负责人是什么？
2. 优先解决的 1–2 个巡视场景和可获得的真实脱敏影像是什么？
3. 首期影像由人工上传还是既有设备平台提供？已有哪些无人机、机巢和接口？
4. 整改闭环是本系统负责，还是与现有台账对接？
5. 原型用途是内部澄清、向领导汇报还是直接指导 MVP？移动端是否必要？
6. 部署环境、网络条件、数据权限和外部模型调用限制是什么？
7. 对验收效果、周期、投入和业务指标有什么实际约束？

以上问题不预设答案；收到新资产及说明后再形成候选 MVP 和架构选项。
