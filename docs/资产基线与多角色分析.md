## 背景与目标：资料表达了什么

需求清单面向施工期大范围、复杂地形工程，强调人工难到达、覆盖不足、巡检取证与整改复核成本高。面向建设单位、监理和施工总包，并延伸提出公路、水利、水运、机电等专项。领导设想进一步提出以 Web 为入口、无人机机巢及相关能力可独立部署，产品为按项目适配的半标品。

目标主链在资料中表现为：任务与航线 → 飞行采集 → 影像归档和识别 → 人工研判 → 整改复核 → 报告与追溯。该链路是方向和原型演示路径，具体系统边界、角色权限及自动化程度未确认。

五大能力域为航线与无人机、采集与影像、AI 隐患研判、整改与报告、平台及集成。需求清单还提出工程量测算、实景三维、热红外、多光谱等扩展；不能据此认定全部进入首期。原型交接页将部分三维、变化检测和工程量等内容描述为中期能力，但这也只是参考方案的分期。

## 明确缺失和冲突

1. 没有可确认的真实试点工程、负责人名单、设备及平台对接人、可用业务数据或现有台账接口；原型示例不能填充这些空缺。
2. 清单涵盖工程量、质量、环保及多个行业；领导重点是无人机安全隐患识别。哪些属于实际产品范围需要决策。
3. 原型以重大隐患人工闸门、部分一般隐患自动流转为例；安全责任、误报漏报、置信度校准及流转授权未验证，不得视作确定业务规则。
4. 参考材料中“自动航线、飞前合规、离线、实时、BIM”等均未说明既有平台能力、外部依赖和产品责任边界。
5. 资料来源、使用许可、保密级别和是否提交 Git 未确认；锁定参考范围不意味着权限已获批准。
